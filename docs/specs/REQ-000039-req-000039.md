## API Contracts

### `hello.greet`

**Signature** (Python, PEP-484 annotated):
```python
def greet(name: str = "world") -> str: ...
```

**Module path**: `hello.greet` (importable as `from hello import greet`).

**Parameters**:
| Name   | Type  | Required | Default   | Constraints |
|--------|-------|----------|-----------|-------------|
| `name` | `str` | No       | `"world"` | Any `str` value. No validation, no normalization. Callers passing non-`str` get standard Python behavior (the `__format__` call inside the f-string will coerce or raise as Python normally would; that path is explicitly out of scope per PRD NG4). |

**Return value**:
- Type: `str`.
- Value: the concatenation `"hello " + name` — i.e., the literal ASCII bytes
  `h e l l o <SPACE>` followed by the characters of `name`, with no trailing
  newline, no punctuation, no capitalization change, no leading whitespace.
- Implementation MUST be `return f"hello {name}"` (single space, double-quoted
  f-string, lower-case `hello`). This is mandated by PRD FR-3 / NG6.

**Preconditions**: None (default argument handles the no-arg case).

**Postconditions**:
- Function is pure: no I/O, no global mutation, no logging, no side effects.
- Determinism: identical inputs produce identical outputs (PRD NFR-1).

**Side effects**: None.

**Raises**:
- Nothing the function itself declares. (Standard `TypeError` semantics of
  f-string formatting apply if a non-`str`, non-formattable value is passed —
  not in scope; no tests cover this path.)

**Usage examples**:
```python
>>> from hello import greet
>>> greet()
'hello world'
>>> greet("ada")
'hello ada'
>>> greet("")
'hello '
```
(Only the first two examples are exercised by tests; the third is illustrative
of behavior and not required to be tested per PRD OQ-1.)

### Module `hello` import contract
- `from hello import greet` MUST succeed without printing anything to stdout
  or stderr, and without raising (PRD FR-8, NFR-7, AT-5).
- `python hello.py` (script execution) MUST print exactly `hello world\n` to
  stdout, with empty stderr and exit code 0 (PRD FR-6, FR-7, NFR-6, AT-3).
- The module MUST contain exactly one top-level function (`greet`) and exactly
  one top-level `if __name__ == "__main__":` block (PRD NG7).

### Test module `test_hello` contract
- File location: repo root, filename `test_hello.py` (PRD TC-5, TC-6).
- MUST be collected by default pytest discovery (no `conftest.py` or
  `pyproject.toml` introduced; PRD TC-3, TC-4).
- MUST contain exactly three pytest-collected functions, all named `test_*`,
  all with `-> None` return annotation, none decorated with

- MUST import `greet` via `from hello import greet` at module top level (PRD
  FR-9, OQ-2). The import MUST NOT be wrapped in `try/except`.

## Drift-Detection Procedure (executor MUST follow exactly)

The executor performs the following ordered steps for TASK-001:

1. **Read `hello.py`**. If its bytes do not match the canonical `hello.py`
   reproduced above (whitespace-significant, including the single trailing
   `\n`), overwrite it with the canonical content. If it matches exactly, do
   not write.
2. **Read `test_hello.py`**. If its bytes do not match the canonical
   `test_hello.py` reproduced above (whitespace-significant, including the
   single trailing `\n`), overwrite it with the canonical content. If it
   matches exactly, do not write.
3. **Verify encoding/line endings**: both files MUST be UTF-8, MUST contain
   only LF (`\n`) line terminators (no CR / CRLF), and MUST end with a single
   trailing `\n` (no double-newline, no missing newline). Verification command:
   ```bash
   python - <<'PY'
   for p in ("hello.py", "test_hello.py"):
       with open(p, "rb") as f:
           b = f.read()
       assert b.decode("utf-8") == b.decode("utf-8")           # valid UTF-8
       assert b"\r" not in b, f"{p} contains CR"
       assert b.endswith(b"\n") and not b.endswith(b"\n\n"), f"{p} trailing newline"
   print("ok")
   PY
   ```
   Expected stdout: `ok`. Exit 0.
4. **Run acceptance tests** (see Test Cases below).
5. **Verify git scope**: `git status --porcelain` MUST show changes ONLY to
   `hello.py`, `test_hello.py`, and files under `.autonomous-dev/` or `docs/`
   (the daemon-owned trees). Any other modified path is a failure.

If at any step a check fails AND cannot be reconciled by overwriting one of
the two target files with its canonical content from this spec, the executor
MUST stop and report a blocker; it MUST NOT introduce additional files,
dependencies, or configuration (PRD NG1, FR-14, TC-3, TC-4).

## Implementation Notes

### Patterns to preserve (from existing codebase)
- Double-quoted string literals throughout (`"world"`, not `'world'`). The
  PRD prose uses single quotes for readability; the *source* uses double
  quotes to match the existing file. The double-quoted form is canonical.
- PEP-484 annotations on every function (`name: str = "world"`,
  `-> str`, `-> None` on tests).
- Blank-line convention: exactly **two blank lines** between top-level
  definitions (PEP 8 / matches existing file).
- `subprocess.run(..., capture_output=True, text=True, timeout=5)` pattern
  with `[sys.executable, str(SCRIPT)]` argv — already present, do not change.
- `SCRIPT = Path(__file__).parent / "hello.py"` for script discovery — do not
  inline this; do not use `os.path`.

### Gotchas
- **No module-level prints.** Anything printed at import time fails TC-4.
  The `print(greet())` call MUST live inside `if __name__ == "__main__":`.
- **No trailing whitespace on `f"hello {name}"`.** A stray space before the
  closing quote will make TC-1 (`"hello world"`) fail.
- **Single trailing newline only.** Many editors helpfully add a second
  trailing newline; verify with the TC-7 check.
- **Do NOT introduce `pyproject.toml`, `requirements.txt`, `setup.py`,
  `conftest.py`, `__init__.py`, or any other file.** PRD FR-14 / TC-3 / TC-4
  forbid this; TC-6 will catch it.
- **Do NOT add `if __name__ == '__main__':` to `test_hello.py`.** Pytest
  discovery does not need it and the canonical content does not include it.
- **Quoting in the f-string**: `f"hello {name}"` — the brace expression is
  `{name}` with no `!r`, no `:>` format spec, no leading/trailing whitespace.

### Similar implementations in the codebase
The current `hello.py` and `test_hello.py` (reproduced in full above) ARE
the canonical implementation. There are no other Python files in the repo
(verified via `Glob` of `*.py` at the repo root returning exactly
`hello.py` and `test_hello.py`).
