## Task List

### TASK-001 — Verify (and, if needed, restore) `hello.py` + `test_hello.py` to match TDD §3

- **ID**: TASK-001
- **Title**: Verify `greet()` refactor and pytest coverage match TDD §3.1 / §3.2; patch if drifted.
- **Description**:
  Confirm that the repository state satisfies the TDD's design exactly. Specifically:
  1. `hello.py` defines `greet(name: str = "world") -> str` returning `f"hello {name}"` (TDD §3.1, ADR-002).
  2. `hello.py`'s `if __name__ == "__main__":` block contains `print(greet())` and nothing else of consequence (TDD §3.1, FR-4).
  3. `hello.py` has no third-party imports (NFR-2).
  4. `test_hello.py` defines exactly the three test functions enumerated in TDD §3.2 / §7 with the assertions specified there, uses `sys.executable` for the subprocess (ADR-003), resolves the script path via `Path(__file__).parent / "hello.py"`, and uses a 5-second subprocess timeout (NFR-1).

  If the working tree already matches (the plan-time observation), no code edits are required — the deliverable is the executed verification commands and the green test run. If any drift is found, apply the minimal patch to restore the contract; do **not** add scope (no input validation, no packaging, no argparse — TDD ADR-001, ADR-004, PRD §2.2).

- **Files**:
  - `hello.py` (read; modify only if drifted from TDD §3.1)
  - `test_hello.py` (read; modify only if drifted from TDD §3.2)

- **Dependencies**: None.

- **Acceptance Criteria** (every item must hold):
  1. `python hello.py` prints exactly `hello world\n`, exits with status `0`, and writes nothing to stderr. (FR-5, NFR-5)
  2. `from hello import greet` succeeds at the Python REPL / inside a test (FR-1).
  3. `greet()` returns the string `"hello world"` (FR-2).
  4. `greet("ada")` returns the string `"hello ada"` (FR-3).
  5. `pytest` run from the repository root exits with status `0`, collects exactly the three tests listed in TDD §3.2, and reports all three as passing. (FR-7, FR-8, FR-9, FR-10)
  6. The full pytest suite completes in well under 5 seconds on a developer laptop (NFR-1).
  7. `hello.py` has no `import` statements (or only standard-library imports if any are added) and ≤ 10 non-blank lines (TDD §3.1 invariants, PRD §8).
  8. No new files are created, no new runtime dependencies are added, and no changes occur outside `hello.py` / `test_hello.py`. (PRD §2.2, NFR-2)

- **Lint/Test Commands** (executor must run all and capture output):
  ```bash
  # 1. CLI contract
  python hello.py
  echo "exit=$?"

  # 2. Unit + CLI tests
  pytest -q

  # 3. Static sanity (no third-party imports in hello.py)
  grep -nE '^\s*(import|from)\s+' hello.py || echo "no imports — OK"

  # 4. LOC budget
  awk 'NF{c++} END{print c " non-blank lines"}' hello.py
  ```
  All four must succeed; `pytest` must report `3 passed`.

- **Estimated Effort**: 15 minutes (≈10 min to run/inspect, ≈5 min buffer for the off-chance of drift requiring a one-line edit). This is below the normal 30-minute task floor; per the "Scale Rigor" rule, splitting it would be ceremony, not value.

- **Track**: N/A — single task.

- **Risks**:
  - **(Low)** Working tree drift between plan authoring and execution could require a tiny restorative edit. *Mitigation*: acceptance criteria are stated in terms of behavior, not file hashes; the executor patches minimally if needed and re-runs the commands above.
  - **(Low)** `pytest` not on PATH in the execution environment. *Mitigation*: invoke as `python -m pytest -q` if the bare `pytest` command is missing — the TDD does not constrain invocation form.
  - **(Low)** No other risks identified — there are no external dependencies, no migrations, no integration points, and no concurrency.
