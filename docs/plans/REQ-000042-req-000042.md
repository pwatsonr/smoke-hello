## Task List

### TASK-001 — Verify (and, if needed, restore) `hello.py` + `test_hello.py` to match TDD canonical shape

- **ID**: TASK-001
- **Title**: Verify `greet()` refactor and pytest coverage match TDD §"Detailed Design"; patch minimally if drifted.
- **Description**:
  Confirm that the repository state satisfies the TDD's design exactly, then attest by running the verification commands listed below. Specifically:
  1. `hello.py` defines `greet(name: str = "world") -> str` returning `f"hello {name}"` (TDD §"Canonical Source Shape", ADR-1).
  2. `hello.py`'s `if __name__ == "__main__":` block contains exactly `print(greet())` and nothing else (TDD §"Canonical Source Shape", PRD FR-6).
  3. `hello.py` has no imports (TDD §"Canonical Source Shape", PRD FR-8).
  4. `test_hello.py` defines the three tests enumerated in TDD §"Test Module Shape" (`test_hello_prints_hello_world`, `test_greet_default_returns_hello_world`, `test_greet_with_custom_name_returns_hello_name`) with the pinned subprocess assertions (returncode == 0, `stdout.strip() == "hello world"`, `stderr == ""`) (TDD §"Test Module Shape", PRD FR-9..FR-11, ADR-2).

  If the working tree already matches (plan-time observation: it does), **no code edits are required** — the deliverable is the executed verification commands and the green test run (PRD OQ-4, TDD ADR-3 explicitly permit a no-op code phase). If any drift is found, apply the minimal patch to restore the canonical shape verbatim from TDD §"Detailed Design"; do **not** add scope (no input validation, no argparse, no packaging, no parametrize refactor — TDD ADR-1/ADR-2/ADR-3, PRD non-goals).

- **Files**:
  - `hello.py` (read; modify only if drifted from TDD §"Canonical Source Shape")
  - `test_hello.py` (read; modify only if drifted from TDD §"Test Module Shape")

- **Dependencies**: None.

- **Acceptance Criteria** (every item must hold; maps to PRD AT-1..AT-7 and TDD §Testing Strategy):
  1. **AT-1**: `python -c "from hello import greet; assert greet() == 'hello world'"` exits 0.
  2. **AT-2**: `python -c "from hello import greet; assert greet('ada') == 'hello ada'"` exits 0.
  3. **AT-3**: `python hello.py` produces stdout exactly `hello world\n`, empty stderr, exit code 0.
  4. **AT-4**: `python -c "import hello"` produces empty stdout and empty stderr (no import-time side effects).
  5. **AT-5**: `pytest test_hello.py` reports ≥ 3 tests passing, 0 failed.
  6. **AT-6**: `pytest test_hello.py -k greet` selects ≥ 2 tests and all selected pass.
  7. **AT-7**: `git status --porcelain` shows changes confined to `hello.py`, `test_hello.py`, and the expected autonomous-dev artifacts under `.autonomous-dev/` and `docs/` (no stray files).
  8. Static contract: `grep -n "def greet" hello.py` returns exactly one match whose signature begins with `def greet(name` and whose default is the lowercase literal `"world"` (TDD §Testing Strategy step 1).
  9. `hello.py` has no `import` statements (PRD FR-8, TDD §"Canonical Source Shape").

- **Lint/Test Commands** (executor must run all and capture output):
  ```bash
  # 1. Static contract checks
  grep -n "def greet" hello.py
  grep -nE '^\s*(import|from)\s+' hello.py || echo "no imports — OK"

  # 2. Behavioral CLI contract (AT-3)
  python hello.py
  echo "exit=$?"

  # 3. Import-time silence (AT-4)
  python -c "import hello"

  # 4. Default + custom-name contract (AT-1, AT-2)
  python -c "from hello import greet; assert greet() == 'hello world'"
  python -c "from hello import greet; assert greet('ada') == 'hello ada'"

  # 5. Full pytest suite (AT-5)
  pytest test_hello.py -q
  # Fallback if `pytest` binary is unavailable:
  # python -m pytest test_hello.py -q

  # 6. Selective greet tests (AT-6)
  pytest test_hello.py -k greet -q

  # 7. Working-tree containment (AT-7)
  git status --porcelain
  ```
  All commands above must succeed; `pytest test_hello.py` must report ≥ 3 passed / 0 failed; `pytest -k greet` must collect ≥ 2 and pass.

- **Estimated Effort**: ~10 minutes (≈8 min to run/inspect commands, ≈2 min buffer for the off-chance of restorative edit). This is below the normal 30-minute task floor; per the "Scale Rigor" rule and the TDD's explicit single-task plan, splitting it would be ceremony, not value.

- **Track**: N/A — single task.

- **Risks**:
  - **(Low)** Working tree drift between plan authoring and execution could require a tiny restorative edit. *Mitigation*: acceptance criteria are stated behaviorally; the executor restores the canonical shape from TDD §"Detailed Design" verbatim and re-runs the verification commands.
  - **(Low)** `pytest` not on PATH. *Mitigation*: fall back to `python -m pytest` (already noted in commands above).
  - **(Low)** Executor over-interprets the task and adds scope (argparse, validation, parametrize). *Mitigation*: TASK-001 description and PRD non-goals explicitly forbid this; TDD ADR-1/ADR-2/ADR-3 pin the canonical shape.

  No medium- or high-severity risks. No external dependencies, no migrations, no concurrency, no integration points, no security surface.
