## 1. Problem Statement

The `hello.py` module must expose its greeting logic as an importable, parameterizable pure function rather than as a top-level side-effecting `print` statement. Without a function boundary, callers cannot:

1. Import the greeting behavior without triggering stdout side effects.
2. Unit-test the greeting directly (only a subprocess-based smoke test is possible).
3. Compose greetings with custom names from other Python code.

The existing repository layout consists of two files at the repo root: `hello.py` and `test_hello.py`. The existing smoke test, `test_hello_prints_hello_world`, spawns a subprocess to verify that `python hello.py` prints `hello world`. This contract MUST be preserved verbatim.

(Verified via `Read` of `/Users/pwatson/codebase/smoke-hello/hello.py` and `test_hello.py` during discovery.)

## 2. Goals and Non-Goals

### 2.1 Goals (in scope)

- **G1.** Introduce a pure function `greet(name: str = "world") -> str` in `hello.py` that returns the string `f"hello {name}"`.
- **G2.** Replace any top-level greeting side effects with an `if __name__ == "__main__":` guard that calls `print(greet())`.
- **G3.** Preserve the existing CLI behavior: `python hello.py` MUST continue to print exactly `hello world` followed by a single newline on stdout, nothing on stderr, exit code `0`.
- **G4.** Add pytest unit tests in `test_hello.py` that import `greet` directly and assert on both the default (`greet()`) and a custom name (`greet("ada")`).
- **G5.** Keep the existing `test_hello_prints_hello_world` subprocess-based test passing without weakening its assertions.

### 2.2 Non-Goals (out of scope)

- **NG1.** Internationalization or locale-aware greetings.
- **NG2.** Input validation, normalization, or sanitization of the `name` argument (no stripping, casefolding, escaping, or truncation).
- **NG3.** Adding a CLI argument parser (e.g., `argparse`) so the user can pass a name on the command line.
- **NG4.** Packaging `hello.py` as an installable distribution or restructuring the repository into a package.
- **NG5.** Introducing linters, type-checker configuration, or CI workflows beyond what is already present.

## 4. User Stories

### Epic E1 — Reusable greeting API

#### US-1 (P0): Programmatic default greeting
- **As a** Python developer importing `hello`,
- **I want** to call `greet()` with no arguments,
- **so that** I receive the canonical string `"hello world"` without producing I/O side effects on import.
- **Acceptance criteria:**
  - **Given** the module `hello` has been imported, **when** I call `greet()`, **then** the return value equals `"hello world"`.
  - **Given** the module `hello` is imported, **when** the import completes, **then** nothing is written to stdout or stderr as a side effect of the import.

#### US-2 (P0): Programmatic custom-name greeting
- **As a** Python developer importing `hello`,
- **I want** to call `greet("ada")`,
- **so that** I receive the string `"hello ada"`.
- **Acceptance criteria:**
  - **Given** the module `hello` has been imported, **when** I call `greet("ada")`, **then** the return value equals `"hello ada"`.
  - **Given** any string `X` passed positionally, **when** I call `greet(X)`, **then** the return value equals `f"hello {X}"` verbatim (no transformation).

### Epic E2 — CLI backward compatibility

#### US-3 (P0): CLI smoke output unchanged
- **As the** repo owner running the smoke test,
- **I want** `python hello.py` to print exactly `hello world`,
- **so that** the existing subprocess-based test and any external smoke scripts continue to pass.
- **Acceptance criteria:**
  - **Given** a Python 3 interpreter, **when** I run `python hello.py`, **then** stdout is exactly `hello world\n`, stderr is empty, and exit code is `0`.

### Epic E3 — Test coverage

#### US-4 (P0): Direct unit tests for `greet`
- **As a** maintainer,
- **I want** pytest unit tests that exercise `greet` directly,
- **so that** regressions in the function are caught without relying solely on subprocess execution.
- **Acceptance criteria:**
  - **Given** the test suite is collected by pytest, **when** it runs, **then** there is at least one test asserting `greet() == "hello world"`.
  - **Given** the test suite is collected by pytest, **when** it runs, **then** there is at least one test asserting `greet("ada") == "hello ada"`.
  - **Given** the existing subprocess test `test_hello_prints_hello_world`, **when** the suite runs, **then** it still passes with its existing assertions intact.

## 5. Functional Requirements

Requirements are numbered `FR-n` and grouped by feature area. Each is testable.

### 5.1 Greeting function (`hello.py`)

- **FR-1.** `hello.py` MUST define a module-level function with the signature `greet(name: str = "world") -> str`. *Verification:* `inspect.signature(hello.greet)` exposes a single parameter `name` with default value `"world"`.
- **FR-2.** `greet()` (no arguments) MUST return the exact string `"hello world"`. *Verification:* `assert greet() == "hello world"`.
- **FR-3.** `greet(name)` MUST return `f"hello {name}"` for any string `name` passed by the caller, with no additional transformation (no stripping, casefolding, escaping, or truncation). *Verification:* `assert greet("ada") == "hello ada"`.
- **FR-4.** Importing `hello` (e.g., `import hello`) MUST NOT print to stdout or stderr and MUST NOT raise. *Verification:* capture stdout/stderr around `import hello` via pytest's `capsys` or a subprocess; both streams must be empty.

### 5.2 CLI entry point (`hello.py` `__main__` block)

- **FR-5.** `hello.py` MUST include a guarded entry point `if __name__ == "__main__": print(greet())`. *Verification:* source inspection plus FR-6 behavioral test.
- **FR-6.** Executing `python hello.py` MUST produce stdout equal to `"hello world\n"`, empty stderr, and exit code `0`. *Verification:* existing `test_hello_prints_hello_world` continues to pass unchanged.

### 5.3 Tests (`test_hello.py`)

- **FR-7.** `test_hello.py` MUST contain a pytest test that imports `greet` from `hello` and asserts the default return value equals `"hello world"`. *Verification:* `pytest -k <test_name>` passes.
- **FR-8.** `test_hello.py` MUST contain a pytest test that imports `greet` from `hello` and asserts `greet("ada") == "hello ada"` (or an equivalent non-default name). *Verification:* `pytest -k <test_name>` passes.
- **FR-9.** The existing test `test_hello_prints_hello_world` MUST remain present and passing. Its assertions on stdout (`"hello world"`), stderr (empty), and return code (`0`) MUST NOT be weakened. *Verification:* diff inspection; pytest run.
- **FR-10.** All tests in `test_hello.py` MUST be discoverable and pass under `pytest test_hello.py` from the repository root using the project's existing Python interpreter and pytest version. *Verification:* integration phase runs `pytest`.

## 6. Non-Functional Requirements

- **NFR-1 (Performance):** `greet()` MUST execute in under 1 millisecond on commodity hardware; the function performs a single f-string formatting and contains no I/O. *Verification:* bounded by absence of loops or external calls.
- **NFR-2 (Test runtime):** The full `pytest` suite MUST complete in under 5 seconds on the existing developer machine. *Verification:* observed wall-clock during integration phase.
- **NFR-3 (Compatibility):** Code MUST run on the Python interpreter already used by the repository (CPython 3, per `sys.executable` usage in the existing test). No new third-party runtime dependencies may be introduced. *Verification:* `pytest` runs without new packages installed.
- **NFR-4 (Style):** New code SHOULD follow PEP 8 (4-space indentation, snake_case, type hints on the public function signature). *Verification:* visual review.
- **NFR-5 (Backward compatibility):** The observable CLI contract (`python hello.py` → `hello world\n`) MUST be preserved byte-for-byte. *Verification:* FR-6.
- **NFR-6 (Security):** `greet` MUST NOT execute or evaluate the `name` argument as code (no `eval`, `exec`, or shell invocation). *Verification:* source review.

## 7. Technical Constraints

- **TC-1.** The repository currently contains only `hello.py` and `test_hello.py` at the root. No package layout, `setup.py`, `pyproject.toml`, or `conftest.py` is in scope.
- **TC-2.** `test_hello.py` already imports `subprocess`, `sys`, `pathlib.Path`, and uses `sys.executable` to invoke `hello.py`. New tests should use direct import (`from hello import greet`) to avoid subprocess overhead.
- **TC-3.** The repository does not declare a Python version pin; the implementation must remain compatible with whatever interpreter `pytest` runs under.
- **TC-4.** No external dependencies beyond pytest (already assumed by the existing test file's idioms) may be added.
