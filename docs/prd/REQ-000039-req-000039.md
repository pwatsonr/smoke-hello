## Problem Statement
The `smoke-hello` repository contains a minimal `hello.py` script used as the smoke-test target for the autonomous-dev pipeline. As currently structured, the greeting logic is embedded directly in the script's `__main__` block, which makes it impossible to import and unit-test the greeting behavior in isolation. This request refactors `hello.py` to extract a reusable `greet(name='world')` function and adds pytest-based unit tests covering both the default and a custom-name invocation, while strictly preserving the existing externally-observable behavior (`python hello.py` prints exactly `hello world`).

This change exists to (a) exercise the autonomous-dev pipeline end-to-end on a small refactor that meaningfully touches both production code and tests, and (b) establish a minimally testable greeting API for future smoke-test requests.

## Goals
- **G1**: Define a function `greet(name: str = 'world') -> str` in `hello.py` that returns the string `'hello <name>'`.
- **G2**: Update the `if __name__ == "__main__":` block in `hello.py` to call `print(greet())`.
- **G3**: Preserve the existing externally-observable behavior: running `python hello.py` MUST print exactly `hello world` followed by a newline (and nothing else) on stdout, with empty stderr and exit code 0.
- **G4**: Add pytest unit tests in `test_hello.py` that import `greet` and verify both the default-argument behavior and a custom-name argument behavior.
- **G5**: Keep the existing script-output test (the test that runs `hello.py` as a subprocess and asserts it prints `hello world`) passing.

## Non-Goals
- **NG1**: No new modules, packages, or files beyond what already exists (`hello.py`, `test_hello.py`).
- **NG2**: No CLI argument parsing (no `argparse`, `sys.argv` handling), no flags, no input prompting.
- **NG3**: No formatting library or templating beyond an f-string or equivalent string concatenation.
- **NG4**: No logging framework, no exception handling beyond Python defaults.
- **NG5**: No type-checking configuration changes (mypy, pyright) and no new tooling/CI changes.
- **NG6**: No changes to capitalization or wording of the greeting (`hello`, lower-case, single space separator).
- **NG7**: No additional functions beyond `greet()` in `hello.py`.

## Functional Requirements

### FR Group A — `hello.py`
- **FR-1**: `hello.py` MUST define a module-level function named `greet`.
- **FR-2**: `greet` MUST accept exactly one parameter named `name` with default value `'world'`.
- **FR-3**: `greet` MUST return a `str` value equal to `'hello ' + name` (single space between `hello` and the value of `name`).
- **FR-4**: `greet()` (no argument) MUST return the exact string `'hello world'`.
- **FR-5**: `greet('ada')` MUST return the exact string `'hello ada'`.
- **FR-6**: `hello.py` MUST retain an `if __name__ == "__main__":` block.
- **FR-7**: The `__main__` block MUST call `print(greet())` and produce no other stdout output.
- **FR-8**: `hello.py` MUST be importable (no side effects at import time other than function definition); i.e., `from hello import greet` MUST succeed without executing the greeting print.

### FR Group B — `test_hello.py`
- **FR-9**: `test_hello.py` MUST import `greet` from `hello` (e.g., `from hello import greet`).
- **FR-10**: `test_hello.py` MUST contain a test function (pytest-style, `test_*`) that asserts `greet() == 'hello world'`.
- **FR-11**: `test_hello.py` MUST contain a test function that asserts `greet('ada') == 'hello ada'`.
- **FR-12**: `test_hello.py` MUST retain a test that runs `hello.py` as a subprocess using `sys.executable` and asserts: exit code 0, stdout stripped equals `'hello world'`, stderr is empty.
- **FR-13**: All tests in `test_hello.py` MUST pass under `pytest` with no test marked `xfail`, `skip`, or `skipif`.

### FR Group C — Scope
- **FR-14**: No files other than `hello.py` and `test_hello.py` MUST be created, modified, renamed, or deleted as part of this change. (Daemon-managed files under `.autonomous-dev/` and `docs/` produced by the pipeline itself are excluded from this constraint.)

### Acceptance Tests (verifiable)
- **AT-1**: `python -c "from hello import greet; assert greet() == 'hello world'"` exits 0.
- **AT-2**: `python -c "from hello import greet; assert greet('ada') == 'hello ada'"` exits 0.
- **AT-3**: `python hello.py` prints `hello world` (with trailing newline), exit code 0, empty stderr.
- **AT-4**: `pytest -q` reports all tests passing, with at least three tests collected from `test_hello.py` (default-arg unit test, custom-name unit test, and subprocess script test).
- **AT-5**: `python -c "import hello"` produces no stdout output (importing must not execute `print`).
- **AT-6**: `git status --porcelain` lists modifications only to `hello.py` and `test_hello.py` (and pipeline-owned artifacts), and no other production source files.

## Non-Functional Requirements
- **NFR-1 (Correctness)**: The `greet` return value MUST be deterministic given the same `name` input; no randomness, no time-dependent output.
- **NFR-2 (Encoding)**: All source files MUST be UTF-8 with Unix (`\n`) line endings and end with a single trailing newline.
- **NFR-3 (Style)**: `hello.py` SHOULD include a return-type annotation (`-> str`) and a parameter annotation (`name: str = 'world'`) consistent with the existing style in the repository.
- **NFR-4 (Test isolation)**: Unit tests for `greet` MUST NOT spawn subprocesses; they MUST exercise `greet` via direct function call.
- **NFR-5 (Test speed)**: The entire `pytest` run MUST complete in under 10 seconds on a developer laptop; subprocess test MUST use a timeout ≤ 5 seconds.
- **NFR-6 (Backward compatibility)**: External CLI contract (`python hello.py` → `hello world\n`) MUST be byte-for-byte preserved.
- **NFR-7 (Importability)**: `import hello` MUST have no observable side effects beyond defining the module and the `greet` function.

## Risks
- **R-1 (Low)**: The implementer could accidentally print at module scope (outside the `__main__` guard), violating NFR-7 / FR-8 and breaking importability. *Mitigation*: FR-6, FR-7, FR-8, AT-5 explicitly forbid and verify against this.
- **R-2 (Low)**: An implementer could use a different greeting format (e.g., comma, exclamation, capitalization). *Mitigation*: FR-3, FR-4, FR-5 and NG6 pin the exact format `'hello <name>'`.
- **R-3 (Low)**: The subprocess test could be deleted or weakened during refactor. *Mitigation*: US-5, FR-12 require it to remain.
- **R-4 (Low)**: A trailing newline difference in `print(greet())` vs. an alternative formulation could cause the subprocess test to fail. *Mitigation*: FR-7 mandates `print(greet())` which uses Python's default `end='\n'`.
