## 1. Overview

This TDD specifies the technical design for refactoring `hello.py` so that its greeting logic is exposed as an importable, side-effect-free pure function `greet(name="world") -> str`, while preserving the existing CLI contract (`python hello.py` → `hello world\n`). It also specifies the pytest unit tests that must accompany this change.

**Design size:** Small. The change introduces exactly one public function (`greet`) and a `__main__` guard in a single module, plus two new unit tests in a single test module. There is no new persisted state, no new external integration, no new dependency, and no protocol. Architecture exploration and ADRs are kept minimal, proportional to the design surface. The full template sections (Architecture, Data Design, Security, Performance) are present but intentionally short — flagged where N/A — per the project's "scale rigor to complexity" guideline.

**Discovered current state (verified via Read of repo root):**

- `hello.py` already contains the target `greet` function and `__main__` guard exactly as required.
- `test_hello.py` already contains the three target tests:
  - `test_hello_prints_hello_world` (subprocess smoke test, preserved verbatim).
  - `test_greet_default_returns_hello_world`.
  - `test_greet_with_custom_name_returns_hello_name`.

The implementation phase MAY therefore be a no-op so long as all PRD functional requirements continue to verify. This TDD documents the contract that the files MUST continue to satisfy and the design choices that have been ratified.

## 3. Detailed Design

### 3.1 `hello.greet`

**Signature:**

```python
def greet(name: str = "world") -> str: ...
```

**Behavior:** Return `f"hello {name}"`. No mutation, no logging, no validation, no transformation of `name`.

**Pseudocode:**

```
function greet(name = "world"):
    return concat("hello ", name)
```

**Parameter kind:** `name` is a regular positional-or-keyword parameter (per FR-1, per PRD R-4). It must NOT be made positional-only (no leading `/`) nor keyword-only (no leading `*`).

**Return:** A new `str` instance equal byte-for-byte to `"hello " + name` (no leading/trailing whitespace beyond what the caller supplies in `name`).

**Side effects:** None.

**Errors raised:** None by design. If a caller passes a non-`str` (e.g., `int`), the f-string will invoke `str.__format__` on the object and produce an unspecified string. This behavior is explicitly out of scope per PRD NG2 / OQ-1.

### 3.2 `hello` module `__main__` guard

**Pseudocode:**

```
if module is being executed as script (__name__ == "__main__"):
    print(greet())
```

**Constraints:**

- MUST use `print(greet())`, NOT `print(f"hello {name}")` or `print("hello world")`. This keeps the CLI output and the function output in lockstep (PRD R-3).
- MUST NOT call `sys.exit()` explicitly; the default exit code is `0` on normal completion (PRD FR-6).
- MUST NOT accept command-line arguments (PRD NG3).

### 3.3 Import-time purity

`hello.py` MUST NOT execute any code at import time other than the `def greet` statement and the `if __name__ == "__main__"` guard. Concretely:

- No top-level `print(...)`.
- No top-level function calls.
- No top-level `logging` configuration.

This is what enables `from hello import greet` inside `test_hello.py` to be silent (PRD FR-4).

### 3.4 Test module `test_hello.py`

Three pytest-discoverable test functions. Test names are part of the contract per PRD Appendix A.

#### 3.4.1 `test_hello_prints_hello_world` (preserved, MUST NOT weaken)

Spawns `python hello.py` as a subprocess and asserts:

- `result.returncode == 0`
- `result.stdout.strip() == "hello world"`
- `result.stderr == ""`

Uses `subprocess.run([sys.executable, str(SCRIPT)], capture_output=True, text=True, timeout=5)` where `SCRIPT = Path(__file__).parent / "hello.py"`. This test predates REQ-000038 and is locked.

#### 3.4.2 `test_greet_default_returns_hello_world`

```python
from hello import greet

def test_greet_default_returns_hello_world() -> None:
    assert greet() == "hello world"
```

#### 3.4.3 `test_greet_with_custom_name_returns_hello_name`

```python
from hello import greet

def test_greet_with_custom_name_returns_hello_name() -> None:
    assert greet("ada") == "hello ada"
```

#### 3.4.4 Import style

The module-level import `from hello import greet` MUST appear at the top of `test_hello.py` (not inside test functions). This both exercises FR-4 (silent import) at collection time and follows PEP 8.

## 4. API Specification

The only public API surface introduced by this requirement:

```python
# hello.py
def greet(name: str = "world") -> str:
    """Return the canonical greeting for `name`.

    Args:
        name: The recipient's display name. Defaults to ``"world"``.
              No validation, normalization, or escaping is performed.

    Returns:
        The string ``f"hello {name}"``.

    Side effects:
        None.

    Raises:
        Nothing by design.
    """
```

**Usage examples:**

```python
from hello import greet

greet()           # -> "hello world"
greet("ada")      # -> "hello ada"
greet(name="bo")  # -> "hello bo"
greet("")         # -> "hello "   (trailing space; intentional, per PRD NG2)
```

**Docstring requirement:** A docstring is RECOMMENDED but not strictly required by the PRD. If the executor adds one, it MUST NOT introduce any import-time side effects (e.g., doctest execution).

## 8. Security Considerations

- **No untrusted input surface.** `greet` accepts a `str` and returns a `str`. No `eval`, `exec`, `os.system`, `subprocess`, or shell invocation (PRD NFR-6).
- **No filesystem or network I/O.**
- **No secrets, credentials, or PII handling.**
- **Subprocess test** uses `sys.executable` (trusted) and a fully-resolved `Path` to `hello.py` (no shell, no user input). Existing pattern, unchanged.

## 9. Performance Considerations

- `greet` is O(len(name)) for a single string concatenation; expected sub-microsecond on commodity hardware (PRD NFR-1).
- No caching needed (pure, cheap, called once per `__main__` invocation and once per unit test).
- Test suite wall-clock budget: < 5 s (PRD NFR-2). The subprocess test dominates due to interpreter startup (~50–200 ms); the two unit tests are negligible.

## 10. Architecture Decision Records

### ADR-1: Keep flat module layout (no package)

- **Context:** Repo has two files at root; PRD TC-1 forbids package restructuring.
- **Options considered:** (a) Leave flat. (b) Promote to a `hello/` package with `__init__.py`.
- **Decision:** (a) Leave flat.
- **Consequences:** `from hello import greet` works because the repo root is on `sys.path` during pytest. No `conftest.py` needed. If the codebase later grows, a future TDD can revisit packaging; out of scope here.
- **Traces to:** PRD TC-1, NG4.

### ADR-2: Regular positional-or-keyword parameter for `name`

- **Context:** `greet(name="world")` could be declared positional-only, keyword-only, or regular.
- **Options considered:** (a) Regular `(name="world")`. (b) Keyword-only `(*, name="world")`. (c) Positional-only `(name="world", /)`.
- **Decision:** (a) Regular.
- **Consequences:** Callers may pass `greet("ada")` or `greet(name="ada")`. Matches the PRD's stated signature exactly and avoids surprising callers. Risk R-4 in the PRD is mitigated.
- **Traces to:** PRD FR-1, R-4.

### ADR-3: `print(greet())` rather than inlining the f-string in `__main__`

- **Context:** The `__main__` block could either call `print(greet())` or duplicate the formatting (`print(f"hello world")`).
- **Options considered:** (a) `print(greet())`. (b) `print("hello world")`. (c) `print(f"hello {name}")` where `name` is hardcoded.
- **Decision:** (a) `print(greet())`.
- **Consequences:** CLI output is coupled to `greet`'s implementation. Changing `greet` automatically changes the CLI, eliminating drift. Mitigates PRD R-3.
- **Traces to:** PRD FR-5, FR-6, R-3.

### ADR-4: Two explicit test functions, not parametrized

- **Context:** PRD OQ-3 leaves the choice open between `pytest.mark.parametrize` and two explicit functions.
- **Options considered:** (a) Two explicit functions. (b) One parametrized function with two cases.
- **Decision:** (a) Two explicit functions.
- **Consequences:** Test names are self-documenting and trace directly to FR-7 and FR-8. Slightly more lines than parametrize; acceptable for two cases. Matches the verified current state of `test_hello.py`.
- **Traces to:** PRD FR-7, FR-8, OQ-3.

### ADR-5: Do not expose `__all__`

- **Context:** PRD OQ-2 asks whether `hello.py` should declare `__all__ = ["greet"]`.
- **Decision:** No.
- **Consequences:** `from hello import *` would still re-export `greet` (it's the only public name). Adding `__all__` is unnecessary scope creep for a single-function module. May be revisited if more symbols are added.
- **Traces to:** PRD OQ-2, NG4.
