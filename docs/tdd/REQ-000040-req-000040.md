## 1. Overview

This TDD specifies a minimal refactor of the `smoke-hello` repository so that
the greeting message is produced by an importable pure function
`greet(name: str = "world") -> str` rather than being inlined in the
`__main__` block of `hello.py`. The script's user-visible behavior
(`python hello.py` prints `hello world`) is preserved, and pytest unit tests
exercise both the default and a custom name.

**Minimal design**: this change introduces no new public API beyond a single
single-line pure function in an existing two-file repo, no new module, no new
data model, no persistent state, no integration point, no protocol, no
dependency. Per the rigor-to-complexity guidance, sections that have no real
design surface (Architecture topology, Data Design, Security, Performance
budgets beyond `< 1 ms`) are explicitly marked N/A below rather than
fabricated.

Inspection of the working tree shows the target shape is already materially
present in `hello.py` and `test_hello.py`. This TDD therefore serves to
**ratify the contract** the executor must preserve and to define **exact
acceptance assertions** the code and code_review phases will use.

### 1.1 Key Design Decisions

| # | Decision | Rationale (traces to PRD) |
|---|---|---|
| D1 | Single positional parameter `name` with default `"world"` (no keyword-only, no `*args`). | FR-1; matches PRD signature exactly; simplest call shape `greet()` / `greet("ada")`. |

| D6 | Existing subprocess test `test_hello_prints_hello_world` is preserved verbatim. | FR-9. |

## 3. Detailed Design

### 3.1 Component: `hello.greet`

A module-level pure function in `hello.py`.

**Signature (Python):**

```python
def greet(name: str = "world") -> str:
    ...
```

**Behavior:**

- Returns the string `"hello " + name` (equivalently `f"hello {name}"`).
- No side effects: no `print`, no logging, no global mutation, no I/O.
- Deterministic: pure function of `name` only (NFR-4).
- Argument `name` is not validated or coerced; type hint advertises `str` and
  callers passing other types receive `__format__`-driven behavior. Per PRD
  OQ-1 this is intentionally undefined; no defensive checks are added.

**Pseudocode:**

```
function greet(name = "world"):
    return "hello " + name
```

### 3.2 Component: `hello.__main__` block

```python
if __name__ == "__main__":
    print(greet())
```

- Calls `greet()` with default argument and prints the result via the
  built-in `print`, which appends `\n` (FR-6).
- Runs only when invoked as a script; importing `hello` does NOT print
  (FR-10).

### 3.3 Component: `test_hello.py`

Three top-level pytest test functions, all in repo-root `test_hello.py`:

1. `test_hello_prints_hello_world` — preserved subprocess test (FR-9).
2. `test_greet_default_returns_hello_world` — asserts `greet() == "hello world"` (FR-7).
3. `test_greet_with_custom_name_returns_hello_name` — asserts `greet("ada") == "hello ada"` (FR-8).

Imports must include `from hello import greet` to exercise FR-10 (importing
must not trigger output). The subprocess test continues to use
`sys.executable` and `pathlib.Path(__file__).parent / "hello.py"` for path
resolution (TC-4).

### 7.3 Import-side-effect guard (FR-10)

The very act of `from hello import greet` at the top of `test_hello.py`
constitutes an implicit guard: if `print(greet())` were not nested inside the
`__main__` block, importing the module from the test runner would emit
`hello world` to captured stdout. While pytest does not by default fail on
that, the `__main__`-guard requirement (FR-10) is verified by inspection
during code_review (the file MUST contain `if __name__ == "__main__":` and the
only top-level statement after `greet` MUST be that guard).

### 7.4 Edge / negative tests

Out of scope. PRD §10 OQ-1 explicitly leaves non-`str` inputs undefined.

## 10. Architecture Decision Records

### ADR-001: Keep the refactor as a single top-level function

- **Context**: PRD FR-1 demands `greet(name="world") -> str` exported from
  `hello.py`.
- **Options considered**:
  1. Top-level function in `hello.py` (chosen).
  2. Class with a `greet` method.
  3. New package `hello/__init__.py` re-exporting `greet`.
- **Decision**: Option 1.
- **Consequences**: Smallest diff, matches PRD signature verbatim, preserves
  TC-1 (no packaging) and NFR-7 (≤ 30 LoC). Options 2 and 3 add ceremony
  with no value for a smoke-test repo.

### ADR-002: Use f-string `f"hello {name}"` rather than `"hello " + name` or `"hello %s" % name`

- **Context**: FR-2 requires exact byte-level output `hello <name>`.
- **Options considered**: f-string, `+` concatenation, `%` formatting,
  `str.format`.
- **Decision**: f-string.
- **Consequences**: Idiomatic Python ≥ 3.6, readable, identical output to the
  alternatives. No measurable performance difference at this scale.

### ADR-003: No CLI argument parsing

- **Context**: PRD NG1 explicitly excludes CLI flags for overriding the name.
- **Decision**: `__main__` block calls `greet()` with no arguments only.
- **Consequences**: No `argparse` import, no `sys.argv` handling. If a future
  PRD adds CLI flags, the design extends cleanly by adding an `argparse`
  block inside the `__main__` guard without changing `greet`.
