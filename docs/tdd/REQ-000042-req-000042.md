## Overview

The PRD requires that `hello.py` expose a pure function `greet(name='world') -> str` returning `"hello <name>"`, that its `__main__` block prints `greet()`, and that `test_hello.py` contain unit tests for both the default and a custom name while preserving the existing subprocess-based script-output test. Inspection of the repository at design time shows both files already meet this contract verbatim:

- `hello.py` defines `def greet(name: str = "world") -> str: return f"hello {name}"` and a `__main__`-guarded `print(greet())`.
- `test_hello.py` defines `test_hello_prints_hello_world` (subprocess), `test_greet_default_returns_hello_world` (default arg), and `test_greet_with_custom_name_returns_hello_name` (custom name).

The technical approach is therefore: **verify the contract holds at code-phase exit; make no changes unless a verification step fails.** If a future code change drifts from the contract, the executor restores the canonical shape documented in §"Canonical Source Shape" below.

## Detailed Design

### Canonical Source Shape

The executor MUST end the code phase with these two files at the repo root.

**`hello.py`** (≤ 15 lines per PRD NFR-3):

```python
def greet(name: str = "world") -> str:
    return f"hello {name}"


if __name__ == "__main__":
    print(greet())
```

Design notes (traceable to PRD):

- Signature is exactly `greet(name='world')` (FR-1). A `str` type annotation and `-> str` return annotation are present; PRD OQ-3 explicitly permits this.
- Implementation is the literal concatenation `f"hello {name}"` (FR-2). No conditional, no formatting beyond f-string interpolation. Pure (NFR-1).
- Module body contains only the function definition and the `__main__` guard. No top-level prints, no top-level expressions with side effects (FR-6, US-4).
- No imports needed (FR-8 — standard library only, and in fact none required).

### API Specification

Single public symbol exported by `hello`:

```python
def greet(name: str = "world") -> str:
    """Return the greeting 'hello <name>'.

    Pure: no I/O, no global state, no time/random dependence.
    Default: greet() == 'hello world'.
    """
```

Validation rules: none. `name` is interpolated as-is into the f-string; PRD FR-2 pins the contract to literal concatenation, and PRD OQ-2 makes additional edge-case behavior (e.g., empty string) optional.

Example usage:

```python
from hello import greet
greet()         # -> "hello world"
greet("ada")    # -> "hello ada"
```

### Test Module Shape

**`test_hello.py`** must contain at minimum the three test functions named below (PRD FR-9, FR-10, FR-11) and must remain discoverable by default pytest rules (FR-12). The canonical shape:

```python
import subprocess
import sys
from pathlib import Path

from hello import greet

SCRIPT = Path(__file__).parent / "hello.py"


def test_hello_prints_hello_world() -> None:
    result = subprocess.run(
        [sys.executable, str(SCRIPT)],
        capture_output=True,
        text=True,
        timeout=5,
    )
    assert result.returncode == 0
    assert result.stdout.strip() == "hello world"
    assert result.stderr == ""


def test_greet_default_returns_hello_world() -> None:
    assert greet() == "hello world"


def test_greet_with_custom_name_returns_hello_name() -> None:
    assert greet("ada") == "hello ada"
```

Design notes:

- The existing subprocess test's three assertions (`returncode == 0`, `stdout.strip() == "hello world"`, `stderr == ""`) are pinned by PRD FR-9 and MUST NOT be weakened.
- The `from hello import greet` at module top performs an import-time side-effect check implicitly: if `hello.py` ever printed at import, the test session header would show stray stdout. The PRD does not require an explicit `test_import_silent`; one may be added but is not mandatory (PRD OQ).
- Parametrization (PRD OQ-1) is permitted but not required. Two separate functions are kept for legibility and so `pytest -k greet` matches at least two tests (PRD AT-6).

## Testing Strategy

Verification at code-phase exit consists of:

1. **Static contract check** — `grep -n "def greet" hello.py` returns exactly one match whose signature matches `greet(name` and whose default is the lowercase literal `"world"`.
2. **AT-1 / AT-2** — `python -c "from hello import greet; assert greet() == 'hello world'"` and `python -c "from hello import greet; assert greet('ada') == 'hello ada'"` exit 0.
3. **AT-3** — `python hello.py` produces stdout exactly `hello world\n`, empty stderr, exit 0.
4. **AT-4** — `python -c "import hello"` produces empty stdout and empty stderr.
5. **AT-5 / AT-6** — `pytest test_hello.py` runs all tests green (≥ 3 passing, 0 failed); `pytest test_hello.py -k greet` selects ≥ 2 tests, all passing.
6. **AT-7** — `git status --porcelain` lists at most `hello.py` and `test_hello.py` (and the autonomous-dev artifacts under `.autonomous-dev/` and `docs/`).

Mapping to PRD requirements: tests directly cover US-1 (G1, FR-1..FR-4), US-2 (G2, FR-5, FR-7), US-3 (G3/G4, FR-9..FR-13), and US-4 (FR-6) by inspection of import behavior.

## Architecture Decision Records

### ADR-1: Keep f-string formatting rather than `"hello " + name`

- **Context**: PRD FR-2 specifies the result is equivalent to `f"hello {name}"` (literal concatenation of `"hello "` and `name`).
- **Decision**: Use `f"hello {name}"`.
- **Alternatives considered**: (a) `"hello " + name` — equivalent for `str` inputs but raises `TypeError` for non-`str`, narrowing the contract; (b) `"hello %s" % name` — older idiom, no benefit here.
- **Consequence**: Matches existing source verbatim, preserves the PRD's "equivalent to f-string" contract, accepts any object supporting `__format__` (loosest contract consistent with FR-2).
- **Trace**: PRD FR-2, NFR-4.

### ADR-2: Two separate test functions instead of `@pytest.mark.parametrize`

- **Context**: PRD OQ-1 permits either shape.
- **Decision**: Keep `test_greet_default_returns_hello_world` and `test_greet_with_custom_name_returns_hello_name` as separate functions.
- **Alternatives considered**: A single parametrized test with two cases.
- **Consequence**: Guarantees `pytest -k greet` selects ≥ 2 distinct test IDs (PRD AT-6) without relying on parametrize ID generation; mirrors the existing on-disk shape, minimizing diff.
- **Trace**: PRD AT-6, OQ-1, NFR-7.

### ADR-3: Permit a no-op code phase if the contract already holds

- **Context**: PRD TC-2 documents that the repo already satisfies all FRs; PRD OQ-4 permits a no-op or minimal-touch commit.
- **Decision**: The executor MUST verify all acceptance tests pass and MUST NOT introduce gratuitous edits purely to produce a diff. If all verifications pass, the code phase commits no source changes.
- **Alternatives considered**: Force a whitespace or comment edit to produce a non-empty diff — rejected as it violates PRD NFR-7 (atomicity) and provides no value.
- **Consequence**: Code phase may produce an empty source diff; downstream phases must tolerate this.
- **Trace**: PRD TC-2, OQ-4, NFR-7.
